# 加密申报账本监控（Crypto Book）

一位**重仓 BTC 的加密投资者**的风险监控页，由 portfolio-watch skill 从
一句话构建。他的账本：0.75 BTC（约占五成四，重仓）、6 ETH、160 SOL，
另有 18,000 USDT 当现金；他给每个仓位定了计划占比（40/25/20/15）。
他的原话："币圈波动太快，我不想整天盯盘，但大事发生时要第一时间知道。"

这个页面回答的就是他这句话背后的三个问题：我的风险到底有多集中？大动
的时候是整个市场在动还是我的币自己出事？什么时候需要我真的做点什么？

## 五条设计原则

1. **先算清"钱实际押在几件事上"。** 表面上持有 3 个币仓，但 BTC/ETH/SOL
   基本同涨同跌（过去 60 天相关性约 0.83），再加上单币重仓——整本账的
   分散程度只相当于约 **2 个互不相关的资产**（这个指标叫有效押注数，
   算法 1/Σw²，满分 3）。这是页面最上方的第一组数字：他集中的不只是
   仓位，更是相关性。

2. **分清"大盘在动"和"这个币自己出事"。** 每个币的涨跌被拆成两部分：
   跟着整个市场一起动的部分，和它自己独有的部分（术语叫 β 与残差；每个
   币的对照组取*其余*两币的平均，避免自己和自己比）。三个币一起大跌 →
   合并成**一条**"大盘事件"，不逐币轰炸；某个币独自异动（且它确实在动，
   不是别人在动衬得它落后）→ 单独提醒"这个币自己有情况，去查它的消息"。
   重仓者最需要的正是这个区分。

3. **按 24/7 市场的规矩办事。** 加密没有收盘价这个锚，涨跌看**滚动
   24 小时**（和它自己过去 20 天的波动水平比）；闪崩闪涨另有一条快线
   （1 小时急动和它平时的小时波动比，超 5 倍才报），而且一段持续下跌
   只在开始提醒一次，之后交给 24 小时口径和亏损档位接管——不逐小时
   轰炸。调度是每小时一次、全年无休：没有"会话窗口"，每次运行都是
   一次判断。

4. **稳定币不看波动，看脱锚。** USDT 仓位按 1 计入市值、汇报占比，
   **从不产生涨跌提醒**——稳定币的风险不是波动是脱锚。脱锚监控走
   USDC/USDT 兑换价对 1.0 的偏离，**连续两次检查确认才报**（≥0.5%
   提醒 / ≥1% 最高级），防止一根毛刺惊动人；兑换价无法区分是哪一边
   在脱锚，提醒文案如实说明。恢复正常后静默复位，下一轮脱锚可以再报。

5. **每条提醒都说清"它帮你做哪个决定"，且规则先被测试钉死。** 是占比
   偏离了自设计划该考虑再平衡，是某个币的逻辑要重新检查，还是亏损触到
   了自己划的线——**绝不给买卖指令**。页面背后的判断代码与 38 条离线
   测试共用同一份，"持续下跌不轰炸""脱锚两次确认""好转不打扰"每条行为
   都有断言钉着。同一判断框架的 A 股实例还经过 12 个月历史回放检验
   （约 3.7 次/月），方法论见 showcase 页。

## 告警规则（preset: normal）

| 规则 | 阈值 | 帮你做的决定 |
|---|---|---|
| 大盘齐动 | ≥2 个币同向 ≥3× 日常波动，且相关性 ≥0.5 → 合并一条 | 看整体风险限额，不逐币反应 |
| 个币异动 | 该币自身部分的波动 ≥3× 它的正常水平（且自身确实在动） | 重新检查这个币的逻辑 |
| 1 小时急动 | ≥5× 它平时的小时波动（持续行情只报开头一次） | 先查发生了什么，别追 K 线 |
| 稳定币脱锚 | USDC/USDT 偏离 1.0 ≥0.5%，连续两次确认（≥1% 最高级） | 核实稳定币仓位的赎回渠道 |
| 占比偏离 | 仓位占比偏离自设计划 ±5pp（回到 1pp 内才重新计数） | 再平衡决策点 |
| 回撤 | −5/10/15/20/30% 逐档，进入与加深才报，好转不打扰 | 对照自己的风险限额 |
| 分散度 | 有效押注数跌破 2.0 | 检查是否过度集中 |

每次运行至多发**一条**汇总消息，按严重程度排序，带"打开 Playbook"按钮；
同一件事只报一次，恶化才追报，好转只默默更新页面。
