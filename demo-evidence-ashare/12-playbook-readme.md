# A 股重仓风险监控 (Showcase)

一位**重仓中际旭创的 A 股投资者**的风险监控页，由 portfolio-watch skill
从一句话构建。他的账本：中际旭创 3,000 股（约占六成四，重仓）、新易盛
1,000 股、天孚通信 1,000 股、贵州茅台 100 股、现金 ¥66 万；他给每个仓位
定了计划占比（50/10/10/5/25）。他的原话："光模块涨太多了，我怕板块一起
回调。"

这个页面回答的就是他这句话背后的三个问题：我的风险到底有多集中？跌的
时候是板块在跌还是我的股票自己出事？什么时候需要我真的做点什么？

## 五条设计原则

1. **先算清"钱实际押在几件事上"。** 表面上持有 5 个仓位，但三只光模块股
   高度同涨同跌（过去 60 个交易日相关性约 0.68），再加上单票重仓——整本
   账的分散程度只相当于约 **1.6 只互不相关的股票**（这个指标叫有效押注数，
   算法 1/Σw²，满分是 4）。这是页面最上方的第一个数字：他集中的不只是
   仓位，更是相关性。

2. **分清"板块在动"和"这只股自己出事"。** 每只光模块股的涨跌被拆成两部分：
   跟着同业一起动的部分，和它自己独有的部分（术语叫 β 与残差；每只股的
   基准取*其余*同业的等权平均，避免自己和自己比）。板块一起大跌 → 合并成
   **一条**"板块事件"，不逐票轰炸；某只股独自异动 → 单独提醒"这只股自己
   有情况，去查它的新闻"。重仓者最需要的正是这个区分。（平台暂无 A 股
   指数数据，故用板块基准而非大盘基准——如实声明。）

3. **A 股的规矩当一等公民。** 涨跌停（创业板 ±20% / 主板 ±10%）是最高
   级别提醒——T+1 之下封死跌停意味着今天想卖也卖不出，这是流动性事件，
   不只是大跌。反过来，"涨跌"超过涨跌停幅度在物理上不可能是真实交易，
   只能是除权除息/送转导致的价格重置 → 当日保持静默，提示核对股数，
   统计中该日收益归零。交易时段 09:30–15:00（含午休，开闭市状态由数据
   本身判断）；中国无夏令时，调度窗口全年不漂移。

4. **每条提醒都说清"它帮你做哪个决定"。** 是某个仓位的占比偏离了你自己
   定的计划、该考虑再平衡了；是某只股的逻辑需要重新检查；还是亏损触到了
   你给自己划的线。**绝不给出买卖指令**——页面提供判断材料，决定是你的。

5. **规则必须先被历史检验过。** 页面内嵌过去 12 个月的回放：把同一套判断
   代码放回历史行情逐日重跑，"这套规则去年会打扰你几次、都在哪些天"一目
   了然（答案：约 3.7 次/月，82% 的交易日安静）。构建期间回放三次推翻了
   规则自己：占比在计划边缘反复穿越会连环报警（→ 加了缓冲）、未复权数据
   把除权日误判成"跌停 −33.9%"（→ 加了除权识别）、回放与实盘逻辑曾有
   分歧（→ 现在两者共用同一份判断代码，回放结论对实盘天然成立）。修复后
   的回放同时显示：这本账过去一年**真实经历过 −20% 级的回撤**——他的
   担忧被历史坐实，而规则会在回撤加深的每一档提醒他。

## 告警规则（preset: normal）

| 规则 | 阈值 | 帮你做的决定 |
|---|---|---|
| 板块同向 | 簇内 ≥2 只同向 ≥3σ 且相关性 ≥0.5 → 合并一条 | 看整体风险限额，不逐票反应 |
| 个股异动 | 该股自身部分的波动 ≥3× 它 60 日的正常水平 | 重新检查这只股的逻辑 |
| 涨跌停 | ±20%（创业板）/ ±10%（主板）触板 | T+1 流动性事件，核对仓位计划 |
| 除权除息 | 「涨跌」超过涨跌停幅度 +2pp（未复权价源） | 无需行动；更新股数 |
| 占比偏离 | 仓位占比偏离自设计划 ±5pp（回到 1pp 内才重新计数） | 再平衡决策点 |
| 回撤 | −5/10/15/20/30% 逐档，进入与加深才报 | 对照自己的风险限额 |
| 分散度 | 有效押注数跌破 2.0 | 检查是否过度集中 |
| 量能 / 跳空 | 收盘量 ≥3× 20 日均量 / 开盘跳空 ≥2σ | 关注信号 / 隔夜消息传导 |

每次运行至多发**一条**汇总消息，按严重程度排序，带"打开 Playbook"按钮；
同一件事只报一次，恶化才追报，好转只默默更新页面。

## 诚实声明

持仓为用户申报并自行维护（送转后需更新股数）；不编造成本价；财报日历
数据仅覆盖美股（A 股财报期提醒缺席，已列盲区）；分红收益未建模（回放
NAV 偏保守）；单一板块基准，非市场基准。**本页为虚构演示数据，不构成
投资建议。**
